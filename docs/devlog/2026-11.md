## 2026-11-14 - English dashboard interface beside Traditional Chinese

### Result

- The dashboard has an English interface in addition to Traditional Chinese. It follows the browser language (`zh*` selects Traditional Chinese, otherwise English) until the header switch overrides it; the choice is remembered in the browser's `localStorage` and the page works without storage. `<html lang>`, the title, and date and time formatting follow the selected language.
- Every user-visible string moved into one dictionary per language in `public/i18n.ts`. No snapshot, API, collector, or alert-text change, and no new runtime dependency. Consumers need no configuration change; the installed artifact gains `public/i18n.js`.
- English labels that the Chinese interface used to show untranslated (filter names such as All, Working, Needs attention, and the filter and tab-move accessibility labels) are now Traditional Chinese there.

### Why / context

- The README and documentation are English, so people evaluating the public repository could not read the product itself.
- Static page text is keyed in the HTML and applied by the module, and dynamic text is rebuilt on a switch by the normal render, so the switch needs no reload and no second code path.
- A key present in one language only is a compile error (the English dictionary is typed from the Chinese one) and a failing test.

### Evidence

- Test first: `test/i18n.test.ts` (dictionary parity, placeholders, HTML keys, language detection, persistence) failed before `public/i18n.ts` existed.
- `scripts/accept-i18n.ts` renders every host and tab in both languages at 1440 px and 390 px from synthetic data on a loopback server; the existing browser acceptance scripts pass with the `zh-TW` locale.

### Links

- <https://github.com/sympoies/host-monitor/issues/64>
- `DEVELOPMENT.md` "Interface language".
