## 2026-09-29 - 0.4.0: Android devices over adb

### Result
- `package.json` version 0.4.0. The server can monitor an Android device attached to its own USB. A host entry with `adb: {"serial": "..."}` (and an optional absolute `bin`) is collected with one read-only `adb -s <serial> shell` call per refresh. `src/android.ts` parses the output in-process, so nothing is installed on the device.
- The snapshot has `platform: android` and a new optional `android` object: battery level, health, temperature, status, and power source; Samsung battery protection; thermal status and HAL sensors; model and release. It also has memory, a `/data` disk row, and two services, the required Termux `sshd` and the optional Tailscale app. The server projection allowlists the new fields. Snapshots stay `schemaVersion` 1.
- Android attention (fleet-infra decision 0003):
  - battery temperature at or above 45 °C;
  - battery health other than good;
  - `/data` at or above 90%;
  - battery protection off while the device is on external power;
  - the Termux `sshd` not running.

  These rules replace the Linux memory and disk thresholds for Android hosts. The new `device` kind is notified by default, and `sshd` is a `service` item.
- A detached, offline, or unauthorized device marks only its host offline and never raises an offline alert.
- The dashboard renders Android hosts with four metrics: battery, battery temperature with thermal sensors, memory, and `/data`. It also shows the `/data` disk row, the `sshd` and Tailscale services, and a host card with battery level and temperature.
- `scripts/build-artifact.ts` ships `src/android.ts`.

### Why / context
- Beszel has no Android agent, and the host-monitor collector cannot run in Termux, because Termux has no Node and no service manager. adb from the server needs nothing on the phone. The evaluation and decision are fleet-infra decision 0003 (serenvia/fleet-infra#44).
- The device's adb serial lives only in the infrastructure repository's server configuration. It never appears in the fleet inventory, in the snapshot, or in the API.

### Evidence
- Test first. Before the change, `node --test test/android.test.ts test/server.test.ts` failed: `src/android.ts` was missing, the runner was never called for adb hosts, an offline alert was posted for a detached device, and invalid adb entries reached the runner. The new alert-kind and acceptance tests failed before `device` was notified and before the dashboard rendered Android metrics. The existing artifact module test failed until `src/android.ts` was added to the artifact.
- The fixture `test/fixtures/android/adb-shell.txt` is real `ADB_SCRIPT` output from a USB-attached Galaxy S22 running Android 16. Battery dates and charge counters are replaced, and it contains no serial.
- A local server with the device attached reported `online`: battery 84%, health good, USB power, protection on, thermal status 0, `/data` 10%, and `sshd` and Tailscale running. A second entry with a missing serial reported `offline`. The rendered page showed four metrics and the `/data` row, with no page errors and no horizontal overflow at 390 px. One collection took about 0.5 s of wall time.
- `npm run validate` passes.

### Links
- serenvia/fleet-infra#44; fleet-infra decision 0003 (`docs/decisions/0003-android-devices.md`); inventory `inventory-v1.4.0` (role `monitoring-android`, transport `adb-usb`).

## 2026-09-28 - 0.3.0: TypeScript, with new entry point paths

### Result
- `package.json` version 0.3.0. All code is TypeScript. Node runs `src/`, `scripts/`, and `test/` directly through its built-in type stripping, with erasable syntax only, so the Node code still has no build step and no runtime dependencies.
- **Consumers must change paths when they upgrade to 0.3.0:**
  - collector: `src/collector.mjs` becomes `src/collector.ts`. This applies to the `collector` path in server configurations and to any direct invocation.
  - server: `src/server.mjs` becomes `src/server.ts`. This applies to the service `ExecStart`.
  - release admission asset: `verify-artifact.mjs` becomes `verify-artifact.mts`. This applies to install steps and checksum lists.
  - Pins to 0.2.0 or earlier keep the old paths.
- The browser app is written as `public/app.ts`. `tsc` emits `app.js` from it: `scripts/build-artifact.ts` emits a fresh copy into the artifact and never reads a local build. The artifact is still self-contained, and the served path `/app.js` and the Content Security Policy are unchanged.
- `typescript` 7.0.2 and `@types/node` 24.19.0 are pinned devDependencies with a committed `package-lock.json`. `npm run validate` now runs:
  - strict `tsc` checks for three configurations (Node, the Playwright acceptance script with the DOM library, and the browser);
  - shell syntax checks;
  - the browser build;
  - the tests.
- CI and the release workflow run `npm ci` first.
- Behavior is unchanged, except:
  - the collector snapshot now places the `attention` key earlier in its JSON;
  - the emitted browser script runs in strict mode.

### Why / context
- Maintainer decision (2026-09-28): TypeScript over JavaScript wherever practical.
- Node 24 is the declared floor, and it strips types by default. `@types/node` tracks that floor.
- `verify-artifact.mts` uses `.mts` because it is downloaded on its own, without the artifact's `package.json`. The extension keeps it an ES module wherever it lands.

### Evidence
- Test first: the tests were renamed to `.ts` and pointed at the new paths, and a new artifact test was added (TypeScript entry points, browser app shipped only as emitted JavaScript that passes `node --check`). Before the conversion the run reported 1 pass and 14 failures, all from the missing `.ts` modules and `scripts/build-artifact.ts`.
- After the conversion, `npm run validate` passes: tsc is clean and 51 tests pass.

- serenvia/fleet-infra#36
- DEVELOPMENT.md, "Entry points changed in 0.3.0" and "TypeScript"

## 2026-09-28 - Per-host scheduling, transition alerts, and event history

### Result
- Each host runs its own collection loop with `refreshSeconds` and
  `timeoutSeconds`; a hung host goes offline alone and never delays the
  others. Staleness is three refresh intervals of that host.
- `src/alerts.mjs` detects attention transitions (new item, recovered item,
  offline after `offlineAfterSeconds`, online again). Items are keyed by kind
  and title.
- Optional `alerts` send one JSON message per transition to a loopback or
  tailnet notification relay in the Apprise API shape, with quiet hours and a
  bounded delivery queue. A token comes only from the environment variable
  named by `authEnv`.
- Optional `stateDir` holds a rotated `events.jsonl` and `alert-state.json`, so
  a restart neither re-notifies nor misses a change. `GET /api/events` and the
  dashboard's recent-events panel read it.

### Why / context
- Alert ownership follows fleet-infra decision 0002: Beszel owns resource
  thresholds and host-down, host-monitor owns service health. History holds
  transitions only, because Beszel stores resource history.
- A history file removed or truncated outside the server is recreated, with
  one fixed-string warning per failure streak.

### Evidence
- `node --test test/alerts.test.mjs` failed with `ERR_MODULE_NOT_FOUND` before
  the change; `npm run validate` passed 49 tests after it.
- A local smoke with a fake collector and a capture relay produced exactly one
  "needs attention" POST and one "recovered" POST. No message was sent to the
  live relay.

### Links
- serenvia/host-monitor#5 (replaces #4), commit f433676
- serenvia/fleet-infra#20

## 2026-09-28 - macOS launchd collector and host identity

### Result
- The collector selects a platform adapter. The Linux path is unchanged; the
  macOS adapter reads launchd without privileges and keeps only a job's type,
  state, pid, run count, last exit status, run interval, and program name.
- Error counts come from `log show --style ndjson`, streamed with a timeout and
  a line cap; only counts and the last timestamp are kept.
- macOS snapshots set `resources` to `external`; the dashboard shows Beszel as
  their resource source.
- An optional host `identity` matches machines whose hostname differs from the
  server host name, compared case-insensitively after removing `.local`.

### Why / context
- fleet-infra decision 0002 scopes host-monitor to service semantics on macOS;
  resource metrics there come from Beszel.
- Environment, arguments, paths, and log message text are never emitted.

### Evidence
- `test/darwin.test.mjs` runs against recorded, redacted `launchctl print` and
  `log show` fixtures, including canary environment and message values.
- `npm run validate`: 36 tests pass. A read-only smoke on a macOS host
  inventoried every loaded job with no collection issues.
